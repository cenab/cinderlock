# Offline source distribution

Use source export when a site admits source and builds its own Cinderlock
executable. Preparation copies public sources, vendors dependencies, and records
toolchain and file identities. Verification and compilation are separate steps;
neither makes an unapproved source tree trustworthy.

> **Note:** This is a preview feature currently under active development.

## Prepare the export

Use an approved Go executable matching the module's required version. Supply
its actual binary path, rather than an older launcher that would download a
toolchain. Preparation can contact the configured Go module sources to populate
the vendor tree; perform it on your admitted preparation machine.

```sh
./bin/cinderlock source export . \
  --go /approved/go/bin/go \
  --include-toolchain /approved/go \
  --helm /approved/helm \
  --helm-notices /approved/helm-notices \
  --out .local/source-export
```

`--go` and `--out` are required. `--include-toolchain` is optional. Supply both
`--helm` and `--helm-notices`, or omit both.
The toolchain directory must be the selected Go executable's actual GOROOT,
with the same executable digest. Symlinked tool paths or distribution members
are rejected. Helm is inventoried and copied; export does not execute or
qualify it.

The Helm notice directory is explicitly operator-admitted and must contain a
nonempty UTF-8 root `LICENSE` or `NOTICE`. Its entire bounded regular-file tree
is copied under `tools/helm-notices` and bound by the inventory; symlinks are
rejected. Correspondence to the selected executable and legal completeness are
not independently attested. The [pinned Helm preparation recipe](../tools/helm/)
produces the binary and matching vendored source/license material together.

The output must be new and cannot be nested inside an admitted source or legal
notice tree.
An ignored `.local/` output is suitable because it is excluded from source
intake. The exporter leaves the original `go.mod` and `go.sum` untouched and
rejects vendoring that changes their copied identities. Local module
replacements are rejected, so vendoring cannot quietly copy an arbitrary local
module into the distribution.

The [source allowlist](../internal/sourceexport/files.go) includes Go build/test
sources, public Markdown documentation, declared schema/example formats,
integration Python sources, deployment templates, the maintained Helm preparation
module/scripts, and root legal/build files.
It excludes `.git`, `.local`, hidden directories, private/credential paths,
environment files, kubeconfigs, private keys, databases, and arbitrary workspace
files. It is a filename/path policy, not a scan proving that selected source
text contains no secrets. Review the admitted source content.

Go files in the selected public `cmd` and `internal` trees remain source code
when their names describe configuration or secret handling. Private directories
and credential data files stay excluded; filename heuristics must not silently
remove code required to compile the selected project.

Traversal and reads use anchored directory handles. Replacing an admitted
directory with an outside symlink cannot redirect a later file copy. Regular
file opens refuse final symlinks and do not block on a substituted FIFO. The
bounded walk also limits visited directory entries. These controls rely on the
host filesystem and trusted operating system; they do not isolate privileged
or same-user access to the process's private working directory.

## Inventory and licenses

The export directory separates `source/`, optional `toolchain/go/`, optional
`tools/helm`, and `BUILD-OFFLINE.md`. `source/vendor/` is freshly generated by
the approved Go command and retains its dependency license copies and module
inventory. The included Go distribution is copied in full, including its
`LICENSE` and regular third-party notice/source files. Root project legal files
and local documentation are included through the public allowlist.

`manifest.json` records module/checksum identities, Go version/platform and
executable digest, optional Helm digest, and every exported regular file's path,
size, mode, and SHA-256. The manifest excludes itself from that file list. CLI
output prints the manifest's canonical object digest as `manifestDigest`.

**Admit that exact expected manifest identity independently.** It is an
inventory, not a signature, producer attestation, vulnerability scan, license
clearance, or key enrollment. An attacker who can replace a tree and its
manifest can recompute hashes; `source verify` alone cannot establish origin.
Move the tree and approved identity through the site's intake process, retaining
the licenses and notices. A source archive created by CI is subject to the same
independent admission requirement.

## Verify received content

Check the received tree and compare its reported manifest identity with the one
already approved for intake:

```sh
./bin/cinderlock source verify /admitted/cinderlock-source
```

Verification checks every listed file and rejects missing, changed, linked,
nonregular, or additional files. Go/Helm identities and module metadata must
agree with the inventory. Keep build outputs outside the inventoried directory;
otherwise a later verification correctly reports an extra file.

Verification observes the received tree; it does not freeze that tree for a
later command. The separate build captures and verifies its own private copy.

If Go was not included, supply an already admitted matching Go distribution on
the build host. The recorded executable hash/version identifies the external
tool; independently admit the rest of that external distribution as well.

## Build a new executable

When the Go distribution is included, it is selected automatically:

```sh
./bin/cinderlock source build /admitted/cinderlock-source \
  --out /approved/build-output/cinderlock
```

Without a bundled distribution, provide its exact matching executable:

```sh
./bin/cinderlock source build /admitted/cinderlock-source \
  --go /approved/go/bin/go \
  --out /approved/build-output/cinderlock
```

`--out` is mandatory, must be outside the source export, and must not exist.
The build verifies the received source, captures a private complete copy, and
requires that copy's manifest and every file to match the initially read
manifest. Compilation reads only this verified snapshot. It checks the Go
identity and uses an empty temporary module cache, fixes local toolchain
selection, disables Go proxy/checksum lookup,
disables CGo, and compiles `./cmd/cinderlock` with `-mod=vendor` and `-trimpath`.
It reverifies the private snapshot after compilation before publishing a
completed, fsynced `0700` executable with an exclusive same-filesystem link. A compile or
verification failure does not publish an executable; an existing file is never
replaced. The build does not run the resulting program.

Bundled Go is selected from the private snapshot. An explicitly supplied Go
path inside the received export is also mapped to the snapshot before any
mutable parent is resolved. An external Go distribution remains separately
admitted host infrastructure: checking its executable identity does not freeze
its entire GOROOT. Protect that distribution throughout the build.

Budget temporary storage for another complete export copy plus compiler cache
and output. The supported intake limit is 100,000 visited entries, 64 path
levels, 4096 bytes per relative path, 1 GiB per file, and 8 GiB of file content;
these are refusal bounds, not peak-space
measurements. Manual compilation from `BUILD-OFFLINE.md` requires an
operator-controlled immutable tree; the managed `source build` command supplies
the verified-snapshot protection described here.

These subprocess settings are local to the operation; they do not modify your
global Go configuration. Disabling online checksum lookup inside the gap is
not an integrity substitute. It relies on already admitted source, vendor
content, and toolchain. This is native compilation for the recorded Go platform,
not GPU, Kubernetes, application, or physical-isolation qualification.

## Validation scope

The [package tests](../internal/sourceexport/export_test.go) acquire a real
fixture module through a local module proxy, preserve its license, then build
with an empty cache and no subsequent proxy requests. They also exercise path
exclusion, public integration/deployment inclusion, symlink/local-replacement
refusal, corruption/extra files, cancellation, output confinement, permissions,
and overwrite/failure protection.

[Race regressions](../internal/sourceexport/races_test.go) exercise directory
replacement, transient source restored before the last verification, and an
input-relative Go path redirected after capture. They use real compilation,
inspect the published bytes and an execution witness, and never run the output.

The environment-gated `CINDERLOCK_TEST_SOURCE_EXPORT=1` test exports the full
project, vendor tree, and Go distribution and compiles from its verified private
snapshot. Run that full gate after the source is frozen. The checked-in GitHub workflow also
prepares this distribution and retains licenses with build artifacts; a
checked-in workflow is not evidence that hosted CI completed. There is no
claim of bit-identical binaries, another host platform, or deployment acceptance.
