# Feature coverage audit

This audit maps the original Gaplane feature catalog, design version 0.2 of
November 7, 2026, to the Cinderlock implementation. The original F01–F50 IDs are
retained for traceability. The alpha contracts in `internal/spec` are the actual
implementation format; the historical design is not a compatibility contract.

> **Note:** This is a preview feature currently under active development.

**Implemented** means a bounded mechanism exists with checked-in tests.
**Partial** identifies an incomplete mechanism. **Unqualified** identifies a
missing deployment or application qualification, even where the mechanism
exists. Labels and test references do not establish live Kubernetes, GPU,
customer restore, or physical-isolation qualification. Fake-client and transport
tests remain distinct from deployment evidence.

## Remaining mechanisms and qualification

The table evaluates the original acceptance conditions, not extra adapters or
universal product behavior. These product mechanisms remain incomplete:

- GitOps mutable data procedures before and after source adoption, plus
  separately authorized restoration (F39). The implemented model/check profile
  rejects those procedures and cannot substitute controller status for them.

The [qualification record](qualification.md) identifies the completed `8db0077`
CPU run with endpoint, resource-budget and measured numeric Jobs. Subsequent
changes need their own receipts; an earlier run never covers later code
automatically.
Qualification remains separate: real GPU/models, identity/browser/scheduled
workflow content, additional hardware/runtime/storage profiles, and customer
restore need approved tests and receipts (F04/F16/F33/F41). Generic Jobs supply
a runner path, not those application tests. Storage combines observed operator
space with admitted remote assertions; it neither measures remote capacity nor
reserves space. Custody signatures do not observe physical transfer or approval.
Independent source/toolchain admission, trusted cluster/storage administration,
retained replay state, and uncertain file/SQLite publication remain operational
boundaries. Evidence attachments preserve producer scope, and catalog imports
are observations rather than current health.

The [architecture](architecture.md) explains these authority and uncertainty
boundaries. Source reuse and licenses are recorded in the
[bundle](REUSE-bundle.md), [engine](REUSE-engine.md), and
[service](REUSE-service.md) implementation notes.
